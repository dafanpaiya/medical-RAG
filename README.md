## 1. 项目概述与动机

### 问题背景

通用大语言模型（LLM）存在出现"幻觉"的情况。在药品合规、QA/QC 检验和法规审计等要求严格、影响严重的情景中，产生“幻觉”内容会导致批次放行无效、审计不通过，甚至带来严重的患者安全风险。

### 解决方案

本项目意图实现了一条**"零无据论断、失败即拒答"的 RAG 问答项目**：

- 每条回答都必须严格锚定在真实的有依据的原文片段上。
- 如果相关证据缺失、含义模糊，或未达到严格的相关性与实体边界阈值，系统会**主动拒答**，返回一个确定性的拒答代码，而不是去猜测。

## 2. 核心工程特性

### 已实现特性

- **混合检索引擎**：将稠密语义向量检索与词法匹配、以及药典精确字符串匹配相结合。
- **药典实体边界强制约束**：专用的边界重排序器可防止不同各论之间的串扰。
- **失败即拒答架构**：对超出范围的提问强制执行确定性拒答。
- **提示词注入与数据边界防护**：不可信的用户输入会被包裹在具有密码学特征的边界守卫中，以防止系统提示词被覆盖、指令被劫持。
- **离线确定性兜底**：在未提供 `API_KEY` 时，可使用本地基于规则的确定性合成器运行。
- **闭环反馈与人工升级**：内置 REST API，用于记录查询、收集用户评分反馈，并将未解决的问题转交人工领域专家。

### 计划中的能力

- **自动化 LLM 语义评判器**：引入自动化语义评估器，实现端到端的定性评分。
- **分布式向量存储**：为大型企业部署提供从轻量级内存向量库迁移到分布式向量数据库（Milvus/Qdrant）的方案。

## 3. RAG 流水线实现

### 3.1 摄取与分块

- **OCR 前的图像提取**：原始 PDF 扫描件使用 PyMuPDF（`fitz`）和 RapidOCR ONNX 引擎处理。
- **表格隔离**：二维表格数据被单独抽离为专属的 `TABLE_CHUNK` 记录，以保留行列关系。
- **完整性锁定**：知识库以密码学方式固定。若 `enterprise_regulatory_kb.json` 或候选文件与其授权的 SHA-256 哈希不匹配，应用将拒绝启动。

### 3.2 混合向量检索

- **稠密哈希嵌入**：高速、确定性的 256 维子词与字符 n-gram 哈希，并做 $L_2$ 归一化（使用 `xxhash`，不可用时回退到标准哈希）。无需占用本地 GPU 显存，也没有外部嵌入 API 的延迟。
- **词法匹配**：双语英文分词，以及中文 CJK 的 1-gram、2-gram、3-gram 切分，配合领域停用词过滤与精确包含加权。

### 3.3 运行时检索参数

- `top_k = 6`：初始混合候选检索池大小。
- `top_n = 3`：重排序后最终保留的候选数量。
- `RAG_SCORE_THRESHOLD = 0.40`：允许生成回答所需的最低综合得分。低于 0.40 的候选会触发自动的 `INSUFFICIENT_EVIDENCE_REFUSAL`。

## 4. 配置说明

可在 `.env` 中配置的关键环境变量：

| 变量名 | 默认值 | 说明 |
|---|---|---|
| `GEMINI_API_KEY` | *（空）* | 可选的 API 密钥。若省略，则使用本地确定性合成器。 |
| `HOST` | `127.0.0.1` | API 服务绑定的网络接口地址。 |
| `PORT` | `8000` | HTTP 服务端口。 |
| `ENVIRONMENT` | `production` | 环境配置档（`production`、`development`）。 |
| `RAG_SCORE_THRESHOLD` | `0.40` | 候选文本块检索的相关性得分阈值。 |
| `RAG_EXPANSION_MODE` | `BASELINE` | 查询扩展策略（`BASELINE`、`CONSERVATIVE`、`LEGACY`）。 |
| `UNIFIED_KB_PATH` | *（内部）* | 可选的统一候选知识库路径（会与 SHA-256 校验值比对）。 |

## 5. 已知局限与技术路线图

1. **药典覆盖范围限制**：
   - 当前受评估的暂存候选集覆盖第四部，并对第二部做了部分映射（共12089条chunk切片）。针对未建索引各论的提问会被正确地"失败即拒答"。
   - 覆盖 4 部药典的跨卷综合索引，仍是进行中的工程里程碑。
2. **自动评分对 OCR 空格敏感**：
   - 确定性事实评分对提取表格与化学符号中的细微空白差异较为敏感。后续工作包括引入自动化 LLM 评判器，以判定语义等价性。
3. **单进程内存向量库**：
   - 当前的 `MedicalVectorStore` 运行在 Python 进程内存中，为演示部署优化了速度与简洁性。面向企业部署，计划横向扩展到分布式向量数据库。
